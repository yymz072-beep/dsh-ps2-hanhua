# 技术参考

> **这些数字来自一个具体游戏**（PS2《新世纪福音战士 绫波育成计划》SLPM-65334）。
> 换游戏时**必须重新摸底**，不要照抄偏移。
> 但格式规律、计算方法、陷阱是通用的。

---

## 1. 光盘镜像结构

### 1.1 判断是不是标准镜像

标准 ISO9660 镜像可以直接读目录树。但很多 PS2 游戏会套一层：

```
ISO9660  →  DATA.BIN（容器）  →  内层 ISO9660  →  真实文件
```

**怎么判断**：读 DATA.BIN 开头，看有没有 `CVMH` / `ROFS` 之类的标记。
内层镜像通常在某个固定偏移（本游戏是 DATA.BIN 的 0x1800），卷标往往被改成别的东西（本游戏是 `SAMPLE_GAME_TITLE`）。

### 1.2 偏移换算

```
内层文件绝对偏移 = DATA.BIN 在外层的位置
                 + 内层镜像在 DATA.BIN 的位置
                 + extent × 2048
```

本游戏：`0x3CD000 + 0x1800 + extent × 2048` → 基准 `0x3CE800`

**容易错**：有些文件（字库、主程序）直接在外层，不用加基准。搞混了会读到完全无关的数据（比如 MPEG 视频头 `00 00 01 BA`）。

**判断方法**：读出来看数据像不像。如果读到的和预期完全不符，先怀疑偏移基准。

## 2. 对话脚本（SCD 类）

### 2.1 两种文本形态

```
对话：  0x0D  <SJIS 文本>  0x00
菜单：  u16 长度  <SJIS 文本>  0x00
```

- `0x0A` = 文本内换行，**不是**终止符
- 前后可能夹 `0x0B` `0x0C` 等控制码

### 2.2 提取器写法

```
扫到 0x0D 或长度前缀 → 一直读到 0x00
期间遇到 0x0A 保留成 \n
```

**坑**：只认 `0x00` 会漏掉所有双行对话（本游戏漏了 17 条）。

### 2.3 长度阈值

不要设死。旁白类长句可能几百字节，阈值小了会整段漏掉（本游戏漏了 12 条长旁白）。

## 3. 字库

### 3.1 游戏内点阵字库（形如 SAMPLE.PF）

本游戏格式：

```
单字 352 字节
  26 行 × 13 字节 = 338（点阵）
  + 14 字节保留
每字节拆两像素：低 4 位 = 左，高 4 位 = 右
一行 13 字节 → 26 像素
→ 26×26 的 4bit 灰度
```

多个块，各自有基址（本游戏 6 个块）。
```
字形地址 = 块基址 + 0x60 + 槽位 × 352
```

### 3.2 借位法（借用不用的格子）

思路：找个没人用的槽位，把中文字形画进去，文本里仍写那个槽位的原编码。

**必须记录三样**：字符、借用编码、槽位（含块基址）。少一样都会出错。

**关键规则**：日文编码首字节落在 `0x88–0x9F` 或 `0xE0–0xEA` 的字，必须借到特定块。否则游戏解码时会落到别的区，显示成完全无关的字。

判断依据：这些范围的首字节本身带"区号"含义，乱放会串区。

### 3.3 外部裸点阵字模（.bin）

用户提供的字模文件，格式看文件名：

```
xxx_全宽14x12_半宽7x12_点阵字模.bin
        ↑宽 ↑高
```

**通用推算**：

```
总字节 ÷ 字数 = 每字字节
每字字节 ÷ 行数 = 每行字节（通常是 1 或 2）
```

已验证规格：

| 规格 | 每字字节 | 解析 |
|---|---|---|
| 16×16 | 32 | 16 行 × 2 字节，取前 16 位 |
| 14×12 | 24 | 12 行 × 2 字节，取前 14 位 |
| 13×13 | 26 | 13 行 × 2 字节，取前 13 位 |
| 12×10 | 20 | 10 行 × 2 字节，取前 12 位 |

**位序**：MSB 在左（最高位是最左像素）。用 `numpy.unpackbits` 直接解。
如果解出来是镜像乱码，换 LSB 再试。

**缺行识别**：14×11 看起来只是少一行，实际是底部整行被截。验证方法——和大一版并排渲染，比底边齐不齐。

### 3.4 字高与描边的关系

| 字高 | 能否配 1px 黑边 |
|---|---|
| 16px | 能，密集字会挤 |
| 14px | 最佳 |
| 13px | 勉强 |
| 12px | 不行 |
| ≤11px | 完全不行，字变黑块 |

原因：字高 ≤12px 时笔画只有 1px 宽，黑边正好吃掉这一像素，字变纯黑。

## 4. 图片

### 4.1 TIM2 结构

```
PIC 头（hs 字节，常见 128）
像素数据在 头偏移 + hs
```

**数据偏移 = 头偏移 + 128**，不是头偏移本身。

### 4.2 ACS 多图容器

一个 ACS 里可能有多张图，必须遍历：

```python
pos = 0
while pos < len(data):
    total = read_total_size(data, pos)
    process(data, pos)
    pos += total
```

**只处理第一张是高频错误。** 本游戏的 `M_STAT.ACS` 第二张图（费洛蒙/疲劳）就这样漏了很久。

验证方法：搜 `TIM2` 标记，看有几个。每个标记后面跟一组数据。

### 4.3 颜色通道

**可能是 RGBA 直接序，不是 BGRA。**

写错的表现：形状对、颜色全错（蓝按钮变土黄）。

判断：导出原图看颜色，如果写回后红蓝对调，就是通道顺序问题。

### 4.4 Alpha（透明度）

原版常见上限是 128（半透明）。

| alpha | 效果 |
|---|---|
| 128 | 原版规格，叠深色背景可见，叠亮背景发白 |
| 180~200 | 折中 |
| 255 | 完全不透明，任何背景都清楚，但挡住背景 |

**如果图是从白底截图做的，必须用 255**，否则叠在亮场景会消失。

### 4.5 白底抠透明

```python
mn = rgb.min(axis=2)
whiteness = clip((mn-238)/17, 0, 1)
alpha = 255 * (1 - whiteness)
```

### 4.6 位置对齐

游戏读图用固定块（64 或 128 像素），UV 写死在程序里。

- 内容必须像素级原位
- **绝对不能整体位移**（平移 64px 会导致相邻按钮串位）
- 验证方法：对比色块起止列

### 4.7 图片归属确认

**改图前先确认这张图属于哪个文件。**

方法：把图缩到 32×32，和全库所有同尺寸图片算相关系数，最相似的通常就是原版对应图。

**本游戏最大教训**：把 `SHP_OBJ.ACS` 的图当成 `M_STAT.ACS` 写入，游戏毫无反应。

## 5. 主程序里的字符串

不是所有文本都在脚本文件里。主程序（ELF）里常有：

- 属性名、状态名
- 物品名称和说明
- 职业/技能表
- 系统提示（存档、读档、记忆卡）
- 随机对话
- 人物名

**格式**：纯 SJIS，`0x00` 结尾，没有长度前缀。

**写入**：读到 0x00 得到原长度，写新译文，不足补 `0x00`（不是空格）。

**格式串限制**：有些提示是"名字 + 助词 + 数字 + 动词"拼接的，助词共用，中文语序做不到。这种要提前告诉用户，不要硬凑。

## 6. 文本回填规则

### 6.1 必须等长

脚本文件里有大量跳转地址。长度变化会让后面的内容全错位——对话跳到别处、黑屏、卡死。

```
短了 → 补 0x20（空格）
长了 → 压缩译文，或问用户能不能简化
```

补空格不补 `0x00`，因为 0x00 是终止符。

### 6.2 长句优先

同一段文本的长短版本同时存在时（比如整句和它的前半句），**必须先换长的**。

否则先换短的会把长的前缀改掉，长的再也匹配不上，结果是半中半日。

处理：按长度降序，换过的区间记录下来，短的跳过。

### 6.3 换之前核对原字节

```python
if data[off:off+len(old)] != old: skip
```

不核对的话，偏移算错就会改坏别处。

## 7. 表格工具坑

### 7.1 Excel 自动转换类型

译文里写"6月10日"，Excel 会存成日期类型，读出来变成 `2026-06-10 00:00:00`，写回游戏就是乱码。

处理：
- 读表时判断类型，日期转回字符串
- 或者提醒用户把那几格设成文本格式

### 7.2 重复条目

同一句可能被两个提取清单各收一次（比如带换行和不带换行的差异）。按原文去重。

### 7.3 用最新表

每次重建都要用用户最新的译表，否则之前的修改会丢。
