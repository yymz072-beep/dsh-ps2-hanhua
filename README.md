# dsh-ps2-hanhua

一个给 AI 用的 **PS2 游戏汉化向导技能**。

不是自动翻译机，是陪你把汉化流程走完的助手：每一步先问清楚，绝不擅自替你做决定。

---

## 这是什么

你在对话里说「开始汉化」，它会按固定流程推进：

```
问清需求 → 摸底分析 → 定方案 → 逐块执行 → 验收
```

每个需要你拿主意的地方，它都会停下来问，并且把选项的好处置于坏处之前写清楚。

---

## 三条铁规矩

### 1. 不许自己做决定

动手前先问："这个决定是用户做的还是我做的？"

答不上来就停下来问。

明确列了不能做的事：
- 替用户选方案
- 猜用户想要什么
- 觉得"这样应该可以"就动手
- 说"我先这样做，不行再改"

### 2. 说人话

不堆术语。比如：

| 术语 | 它会说成 |
|---|---|
| 借位法 | 借用游戏里暂时用不到的格子，把中文字画进去 |
| 点阵字库 | 用一个个小方块拼出来的字，像马赛克 |
| 等长替换 | 换字时字数不能变，变长了后面的内容会全部错位 |

### 3. 选项摆清楚

每个选择都给至少两个方案，标注推荐项，好处坏处都写，不藏着掖着。

## 流程概览

### 阶段零：开工前问清楚

问四件事，一次问一到两个：

1. 什么游戏？什么平台？镜像在哪？
2. 汉化到哪个程度？（只翻文字 / 文字+图片 / 全都做）
3. 翻译谁来做？（AI 翻你校对 / 你出空表 / AI 先做一版你改）
4. 字库怎么办？（用现成字体转 / 生成点阵 / 你已有）

### 阶段一：摸底

只看不动。统计文本量、图片数量、字库格式，出一份报告。

### 阶段二：带数据确认方案

拿着摸底结果问，比空问有效。

### 阶段三：逐块执行

每改一处立刻从成品读回验证。遇到看不懂的现象停下来描述，不猜着改。

### 阶段四：验收

出清单：完成了什么、验证了什么、已知问题、需要你试玩确认的。

## 内置的技术积累

`references/technical-notes.md` 里是实际项目中踩出来的经验：

- 镜像三层嵌套的偏移换算
- 对话脚本的两种格式和提取器写法
- 点阵字库格式推算公式（总字节 ÷ 字数 = 每字字节）
- 借用空闲格子的规则（为什么有的字会显示成完全无关的字）
- 图片容器可能有多张图，只处理第一张会漏
- 颜色通道可能是红蓝反的
- 透明度的取值和背景明暗的关系
- 12 像素以下的字为什么不能加描边

**注意**：里面的具体偏移来自一个特定游戏，换游戏必须重新摸底，但格式规律和陷阱是通用的。
